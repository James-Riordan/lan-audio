# Version 2: preserve samples and bound the byte stream

Status: **implemented pure codec** in [v2.zig](../../src/protocol/v2.zig), with
[Format](../../src/media/format.zig) and a separate
[record-order gate](negotiation.md). Independent oracle/fixture-mTLS qualification
now exists; production transport/device integration remains unfinished. V1 bytes, ALPN
and Receiver retain their existing meaning. `wire_v2` is a separate core export.

## Domain and layer boundaries

The initial application format is stereo, interleaved IEEE-754 binary32, rates
44100/48000/96000 frames/s, and 1..1024 frames/record. These are permitted protocol
formats, not a statement that every native device supports them. The host must
validate actual endpoints before sending ACCEPT. No automatic conversion is hidden
in the codec. No codec call authenticates a peer, opens a device or allocates memory.

`Format.validate` rejects unsupported dimensions. `sampleCount(n)=2n` and
`byteCount(n)=8n` are evaluated only after proving `1<=n<=max_frames<=1024`.
Thus the largest product is 8192 and fits the supported target integer widths.
`Format.eql` compares every dimension; ACCEPT must echo rather than negotiate
by silent substitution. Stream IDs are nonzero 16-byte values; unpredictable fresh
ID generation and peer binding belong to the host, not this validator.

## Canonical wire representation

The negotiated ALPN is `jcr-audio/2`. All fixed-header integer fields are unsigned
big-endian. Audio sample words alone use little-endian encoding.

| Offset | Width | Meaning / admission rule |
| ---: | ---: | --- |
| 0 | 4 | ASCII JCR2 |
| 4 | 1 | Version 2 |
| 5 | 1 | OFFER=1, ACCEPT=2, AUDIO=3, END=4, ACK=5 |
| 6 | 2 | Header size exactly 48 |
| 8 | 4 | Body size exactly the kind/count-derived size |
| 12 | 4 | Flags zero |
| 16 | 16 | Nonzero stream ID |
| 32 | 8 | Source frame position |
| 40 | 4 | Frame count |
| 44 | 4 | Reserved zero |

OFFER and ACCEPT have position/count zero and a 16-byte body: rate u32, channels
u16 (=2), representation u16 (=1), max_frames u32, reserved u32 (=0), all BE.
AUDIO has count 1..1024 globally, subsequently restricted by the negotiated format,
and exactly count*8 body bytes. END and ACK have count/body size zero and carry an
exclusive frame frontier. Empty streams may end at zero.

For AUDIO, reject `position > max_u64 - widen_u64(count)` before any addition.
The final representable exclusive frontier max_u64 is legal; no nonempty audio
can begin there. This differs from v1's block-index rule and must not be merged
into an apparently universal sequence helper. The pure codec accepts any valid
position; the gate requires it equal the current contiguous frontier.

No flags, rates, channel layouts or representations have extension meaning unless
specified. Unknown values fail explicitly. Future incompatible behavior requires
a compatibility decision and its own tests, not permissive parsing today.

## Why finite values survive exactly

Let W be the 32-bit memory word of a sample and E its exponent bits. A sample is
admissible precisely when `W & 0x7f800000 != 0x7f800000`. This excludes both signs
of infinity and every quiet/signaling NaN encoding without floating arithmetic.
Every admissible word, including both zeros and subnormals, is serialized by four
little-endian bytes and reconstructed by the inverse integer operation and bitcast.
Therefore reconstructed W equals original W. This is a representation argument,
not a claim that resampling or acoustic output preserves the same bit pattern.

Validation precedes all output writes. An encoder validates dimensions, finite
words, ID, position and output extent; the decoder validates the complete message
and exact output length. After that point, bounded copies/word stores cannot raise
a recoverable validation error. All encoder/decoder input and output storage must
be disjoint. Avoiding an extra decode temporary is safe only under this aliasing
precondition; v1's overlap allowance does not transfer to this API.

## Streaming parser argument

Parser storage is exactly 8240 bytes. Its representation invariant is
`0<=used<=wanted<=8240`; wanted initially equals 48. A validated header chooses
either 48, 64 or 48+8n, never a caller-provided allocation size. Each feed copies
`min(wanted-used, input_remaining)` bytes. It can complete the header and body,
then returns after at most one record. An incomplete copy returns immediately,
including an empty feed, so a zero-progress internal spin is impossible.

The caller retains the unconsumed suffix. A returned Message borrows parser memory
only until the next feed, even an empty one. Process/copy it before continuing.
Any framing/profile/sample failure poisons the parser. A fresh parser is for a
fresh connection; it is not a way to skip a malformed record within a stream.
`finish` verifies framing completeness only. It cannot establish END/ACK, a clean
TLS close, receiver quiescence or acoustic completion.

## Call-by-call contract

| Surface | Input and output | Failure / owner obligation |
| --- | --- | --- |
| `parse(bytes)` | Exactly one complete record; Message borrows bytes. | Reject truncation/trailing bytes, unknown fields and invalid values. |
| `validate(message)` | Caller-constructed Message is revalidated. | Typed construction does not bypass untrusted-input checks. |
| `profile(message)` | Copy Format from OFFER/ACCEPT only. | Reject other kinds and invalid dimensions/reserved fields. |
| `Parser.feed(input)` | Copy consumed prefix into fixed storage; at most one borrowed Message. | Serialized owner; input cannot overlap storage; first error poisons. |
| `Parser.finish()` | No state mutation; accept empty/complete frame state. | Poisoned or Truncated for incomplete/failed framing. |
| `encodeProfile(out,kind,id,format)` | OFFER/ACCEPT only; borrow written prefix. | All invalid input/short output leave out unchanged. |
| `encodeControl(out,kind,id,position)` | END/ACK only, 48 bytes. | Does not attest drain; gate/host must authorize the control message. |
| `encodeAudio(out,id,position,samples,format)` | Nonempty complete stereo frames; preserve finite bits. | Reject nonfinite/oversize/odd-length/overflow before writing; no overlap. |
| `decodeAudio(message,out)` | Exact count*2 output samples. | Reject any invalid sample before all output writes; no overlap. |

Private `bodySize` owns kind-specific extent arithmetic; `header` validates envelope
fields before admitting body bytes; `readProfile` validates the format; `finiteWord`
owns the exponent mask; `writeHeader` performs no fallible work after its checks.
Changing one requires reviewing the shared bound and failure-atomicity argument.

## Cost and evidence

Encoding and decoding each inspect O(n*channels) samples; the parser copies each
input byte once into its storage and validates complete audio words. The gate
revalidates Messages so direct constructed input cannot bypass checks. This means
some scans are intentionally repeated; removing them needs a real trusted-message
type/lifetime boundary and a measured reason. No zero-copy or numeric latency claim
is made. Large Parser objects belong in stable worker storage, not callback stacks.

[Unit tests](../../tests/unit/protocol/v2.zig) check literal independent wire vectors,
131,072 finite sample patterns including explicit boundaries, every incomplete split
of an 8240-byte record, coalescing, malformed fields and unchanged rejected outputs.
[Current evidence](../../verification/fidelity-core/RESULTS.md) records actual runs.
[Independent qualification](../verification/v2-independent.md) adds bounded
differential testing and fixture-mTLS application peers. Native capture-to-playback
v2 execution remains a WP04 gate. Tests do not exhaust all finite float values or
all arbitrary byte strings.
