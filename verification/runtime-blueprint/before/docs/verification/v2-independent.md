# Independent v2 checks and authenticated application roles

Status: executed test infrastructure, not a product executable or public FFI.
The [wire contract](../protocol/v2.md) and [state gate](../protocol/negotiation.md)
remain canonical. This chapter explains what the independent checks actually show.

## Independent oracle and fixed-storage probe

[`protocol_v2_reference.py`](../../tests/integration/protocol_v2_reference.py)
constructs/validates records with Python struct and integer sample words. It does
not call Zig to derive expected lengths, headers or sample bytes and does not
convert sample words to Python floats. It is an independent implementation of the
same written specification, not an independent interpretation of the user's goal.

[`v2_codec_probe.zig`](../../tests/integration/v2_codec_probe.zig) exports a test-only
C function that compares production stateless and fragmented parsing, then decodes
and re-encodes accepted records. Input is capped at 8241 bytes, parser storage at
8240, decoded scratch at 8192. Caller pointers/lengths must be valid and disjoint.
The function retains no pointer and performs no allocation or I/O.

Return zero means invalid exactly-one-record input. A positive length means a
canonical re-encoding. Negative values identify misuse or disagreement among
production paths; the harness must never count those as a successful rejection.
Malformed parser errors must poison later feed/finish. A truncated or extra-byte
record must agree with the reference on rejection. Accepted output must equal the
independent input byte-for-byte, and rejected output must retain its sentinel bytes.

The tested relations are, for each generated byte string b and fragment f:

`Accept_reference(b) = Accept_parse(b) = Accept_feed_then_finish(b,f)`

and, when accepted, `Encode(Decode(b)) = b`. The wrapper treats unconsumed trailing
bytes as rejection to match the exactly-one-record predicate; production Parser
itself correctly leaves coalesced suffixes to its owner. This is evidence for the
tested domain, not an unbounded equivalence proof or a replacement for state checks.

## Reproduction and resource bounds

```powershell
zig build v2-codec-probe -Doptimize=ReleaseSafe -j1 --summary all
python tools/test_v2_differential.py --output verification/NEW-RUN/differential.json
zig build v2-transport-probes -Dtransport-tests=true -Doptimize=ReleaseSafe -j1 --summary all
python tests/integration/protocol_v2_peer.py --output verification/NEW-RUN/interop.json
```

Choose a fresh report filename. Both runners refuse existing reports and require
paths under verification. The differential runner loads only a library in this
project's zig-out tree. Its 120-second killable child evaluates at most 14,000 cases
of at most 8241 bytes, streams a fixed-seed corpus and retains the last in-flight
case for a native crash/hang reproducer. It does not impose a whole-process OS
memory quota; bounded buffers/case generation are distinct from such a quota.

The corpus contains valid profiles/rates/block sizes/terminal frontiers, every
truncation of a maximum record, every single-bit mutation in three representative
headers, and 4,000 seeded body/header/length/arbitrary-byte mutations. Fragment
sizes cross byte/header/record boundaries. Reports record seed, corpus hash, binary
hash, elapsed time and accepted/rejected totals. A deterministic run may reproduce
the same count while missing other bugs; broad random fuzzing is not exhaustive.

## Authenticated interoperability and exact scope

[`tls_v2.zig`](../../tests/integration/tls_v2.zig) builds two test executables from
one source using a compile-time application role. Both are TLS clients. The separate
Python implementation is the TLS server, acting as the opposite media role. This
qualifies both **application** directions; it does not qualify a native Zig TLS
server, public discovery/listening or two physical devices.

The programs use mutual certificates, exact v2 ALPN, localhost name verification,
reviewed private OpenSSL DLLs and public fixture keys with an explicit frozen test
clock on the Zig side. The network adapter is restricted to ephemeral loopback and
forces short transfers. Production code must supply actual endpoints, authorization,
credentials and certificate time; these defaults must not be copied into it.

Application blocks are 1,17,240,1024,3 frames (1285 total), including signed zeros,
subnormals, normal boundaries and finite extrema. The receiver compares each word;
the Python receiver compares complete independent bytes. This synchronous test
sink has no asynchronous callback/device owner. Its ACK attests completion of
sample verification, not native queue/device drain or acoustic output.

Twenty-two scenarios cover both successful roles, an empty stream, rejected profile,
audio before negotiation, wrong stream, duplicate/gapped positions, nonfinite data,
truncation, missing END/ACK, data after terminal control, raw EOF, stalled peer,
wrong ALPN/name, altered ACCEPT and wrong ACK. Success requires matching bytes/
frontier, independent peer state, clean TLS close and a successful process exit.
Negative cases require the named error and absence of the success marker; unrelated
crashes/timeouts are failures of qualification. Socket/process/thread deadlines are
recorded in source, and every peer must terminate.

## What remains

The core protocol's independent-peer and bounded differential gates now have local
evidence. Real device formats, native Mac build/execution, credentials/peer policy,
capture assembly integration, callback drain, pacing/drift and impaired-NIC recovery
remain distinct product gates. Existing TLA+ models do not automatically prove
the new probe, assembler or production protocol composition. Exact runs and limits
are in [the phase report](../../verification/v2-independent/RESULTS.md).
